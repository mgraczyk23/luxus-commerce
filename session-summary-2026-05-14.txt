7. PRODUCT IMPORT API
   Endpoint: POST /import/products
   Auth: X-Api-Key header (LUXUS_IMPORT_API_KEY env var)
   - Accepts single product object or array for bulk import
   - Creates Medusa product + default variant with optional pricing
   - Creates product_details, product_specs, inventory_info records in parallel
   - Resolves attribute values by type slug + value text (case-insensitive)
   - Unknown slugs/values reported as warnings, don't fail the import
   - Per-item error handling for bulk imports (some can fail, others succeed)
   - Returns: { created, failed, results: [{ title, product_id, success, error?, warnings? }] }

   Example payload:
   {
     "title": "Nighthawk Custom Agent",
     "sku": "NHC-AGENT-01",
     "price": 3499.00,
     "status": "draft",
     "details": { "serial_number": "NHC-12345", "optics_ready": true },
     "specs": { "overall_length": "8.75\"", "weight": "38 oz" },
     "inventory": { "item_cost": 2800, "is_backroom": false },
     "attributes": { "brand": "Nighthawk Custom", "caliber": ".45 ACP" }
   }

NEW FEATURES ADDED TO SCOPE (not in original SOW)
--------------------------------------------------------------------------------

1. BACKROOM / VIP SYSTEM
   Two-flag approach for inventory visibility control:
   - is_master_backroom: item exists in backroom pool but NOT shown in VIP display
   - is_backroom: item is actively displayed in VIP area
   This allows on-the-fly curation of what VIP clients see without removing items
   from the backroom pool. The storefront VIP area will need password protection.
   Admin-only fields; not in original module specification.

2. PRODUCT IMPORT API
   The SOW referenced a bot/AI agent for product management but did not specify
   a dedicated import endpoint. This was built as a standalone authenticated API
   separate from the Medusa admin routes, using a static API key rather than
   JWT auth, making it suitable for programmatic/bot use without token refresh.

3. CONSIGNMENT PORTAL FOUNDATION
   Added consignor_customer_id field to link consignors to Medusa customer
   accounts. This is the data layer needed for a future consignor portal where
   consignors can log in and view their items. The portal UI and auth flow are
   not yet built.

4. ATTRIBUTE MANAGEMENT UI
   The SOW assumed attributes would be managed via direct DB/API. A full
   attribute management page was built in the admin for non-technical management
   of attribute types and values without needing API access.

5. UNIFIED PRODUCT CREATE PAGE
   The SOW did not specify admin customization beyond standard Medusa. A fully
   custom product creation page was built that combines Medusa native fields
   with all four custom modules in a single form, eliminating the two-step
   create-then-edit workflow that the standard Medusa wizard would require.
